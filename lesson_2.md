#### Шпаргалка команд по второму уроку

<details>
<summary>Отмена изменений</summary>
✅ До индексации (файл еще не добавлен через git add, только внесли изменения):

```sh
git restore <file>
```

✅ После индексации (файл добавлен через git add), но до коммита:

```sh
git restore --staged <file>
```
</details>

<details>
<summary>Отмена коммитов с сохранением истории безопасно при работе с удаленными репозиториями</summary>
✅ Изменить последний коммит (сообщение коммита или содержимое файлов)

```sh
git commit --amend -m "новое сообщение"
```

✅ Безопасная отмена любого коммита (с сохранением истории)

При этом состояние наших файлов откатывается к состоянию, которое было в коммите на который мы ссылаемся в команде revert

```sh
git revert <commit-hash>
# или
git revert HEAD
```
</details>
<details>
<summary>Отмена коммитов с изменением истории !!!НЕ ИСПОЛЬЗОВАТЬ ПРИ РАБОТЕ С УДАЛЕННЫМИ РЕПОЗИТОРИЯМИ!!!</summary>
✅ Отменяет коммиты, но оставляет изменения в индексе (готовы к новому коммиту).

```sh
git reset --soft <commit>
```
--soft

Что делает?
Перемещает указатель HEAD на указанный коммит.
Сохраняет все изменения в индексе (staging area) и рабочей директории.
Все изменения, которые были внесены после указанного коммита, остаются в состоянии "подготовленных к коммиту" (staged).

Когда использовать?
Когда вы хотите отменить последний коммит, но сохранить все изменения, чтобы их можно было перекоммитить или доработать

✅ Отменяет коммиты, убирает изменения из индекса, но оставляет в рабочей директории.

```sh
git reset --mixed <commit>   # или просто git reset <commit>
```
--mixed (значение по умолчанию)

Что делает?
Перемещает указатель HEAD на указанный коммит.
Удаляет изменения из индекса (staging area) , но оставляет их в рабочей директории.
Изменения становятся "неподготовленными" (unstaged), и вам нужно снова добавить их в индекс (с помощью git add), чтобы закоммитить.

Когда использовать?
Когда вы хотите отменить последний коммит и разобрать изменения, чтобы решить, какие из них нужно снова добавить в индекс.

✅ Полностью удаляет все изменения после указанного коммита (из индекса и рабочей директории)

```sh
git reset --hard <commit>
```

--hard
Что делает?
Перемещает указатель HEAD на указанный коммит.
Полностью удаляет все изменения, связанные с коммитами после указанного:
Изменения удаляются из индекса (staging area).
Изменения удаляются из рабочей директории.

Когда использовать?
Когда вы уверены, что хотите полностью удалить все изменения, связанные с последними коммитами, и вернуться к предыдущему состоянию.

<details>
<summary>Временное хранилище GIT</summary>
✅ Спрятать изменения.

```sh
git stash
# или с описанием
git stash push -m "сообщение"
# или включая новые (untracked) файлы
git stash -u
# или только проиндексированные изменения
git stash push --staged
```

✅ Просмотр и восстановление изменений.

```sh
git stash list          # список спрятанных изменений
git stash show          # краткий обзор последнего стеша
git stash show -p       # подробный diff

git stash apply         # применить последний стеш (остаётся в списке)
git stash pop           # применить и удалить из списка

git stash apply stash@{1}  # применить по номеру
git stash pop stash@{1}    # применить и удалить по номеру
git stash drop stash@{1}   # удалить без применения
```

</details>
<details>
<summary>Работа с ветками</summary>

✅ Создать ветку (без переключения на неё).

```sh
git branch <branch-name>
```

✅ Создать и сразу переключиться на ветку

```sh
git checkout -b <branch-name>
# или (новый синтаксис)
git switch -c <branch-name>
```

✅ Просмотр веток.

```sh
git branch        # локальные ветки
git branch -r     # удалённые ветки
git branch -a     # все ветки
git show-branch   # детальный вывод по веткам и коммитам
```

✅ Просмотр истории всех веток в виде графа.

```sh
git log --all --graph
```
✅ Удаление ветки


```sh
git branch -d <branch-name>   # безопасное удаление (только если изменения слиты)
git branch -D <branch-name>   # принудительное удаление
```
</details>
